# تقرير خطة المنصة — مِرْباح (التجار + اللوحات)

> تنفيذ مراحل بترتيبك، مع بقاء المشروع قابلًا للاختبار بعد كل مرحلة.
> كل ما هنا اختُبر فعليًا عبر خادم يعمل وقاعدة SQLite.

## ١) مراجعة البنية وشرط التوقف

- راجعت `prototypes-v3/03-daftar` و`server/server.js`، ونظامهما محلي (localStorage) بلا حسابات.
- **تعارض محتمل واحد** اكتُشف قبل التنفيذ، وحُلّ دون إعادة عمل:
  1. الشجرة والاقتراحات كانت **ثابتة في JS**. لو أنشأ المالك منتجًا جديدًا لن يظهر.
     الحل المطبَّق: جدول `catalog_*` في SQLite يبذر من ملف كتالوج (ESM) و`server/seed-suggestions.js`، والواجهة تسحب الشجرة من `/api/public/catalog` عبر `js/catalog-sync.js`، مع احتياط محلي عند غياب الشبكة.
  2. حالة الحاسبة كانت مجهولة الهوية. أضيف **`projectId`/`productId`** في الرابط، و`/public/?project=…&product=…&start=1` يفتح الحاسبة على المنتج، ثم تُحفظ عبر `PUT /api/merchant/products/:id`.
  3. لم توجد مصادقة. أضيفت جلسات على الخادم + كلمات مرور scrypt + أدوار.
- لا تغيير تقني: Node 26 و`node:sqlite` فقط، بلا حزم خارجية.

## ٢) معمارية الاتصال

| الطبقة | المسار | الحماية |
|---|---|---|
| واجهة الزائر | `/public/*` → `/api/public/*` | قراءة فقط |
| مصادقة | `/login` `/register` `/owner-login` → `/api/auth/*` | جلسة كوكي httpOnly + SameSite=Strict |
| لوحة التاجر | `/dashboard/*` → `/api/merchant/*` | دور `merchant` + ملكية المشروع |
| لوحة المالك | `/owner-admin/*` → `/api/owner/*` | دور `owner` + اختياري TOTP |

التشغيل: `npm start` → `tools/start-platform.js` (تهيئة + بذر + إقلاع).

## ٣) قاعدة البيانات (SQLite)

جداول: `users, sessions, projects, categories, products, recipes, catalog_activities, catalog_categories, catalog_products, catalog_suggestions, ingredient_library, price_sources, ai_settings, ai_logs, site_content, theme_settings, audit_log, login_attempts, backups, meta`.
- بذر الكتالوج: **19 نشاطًا · 49 تصنيفًا · 66 منتجًا · 377 اقتراح مكوّن**.
- نسخة احتياطية تلقائية قبل أي بذر (`server/data/backups`).

## ٤) الأمان (الفصل الحقيقي)

| الضمانة | كيف | اختبار |
|---|---|---|
| الزائر لا يدخل اللوحات | حارس صفحات على الخادم | ✓ 302 إلى `/login/` |
| التاجر لا يصل لـ API المالك | فحص الدور لكل طلب | ✓ 403 `forbidden` |
| المالك لا يستخدم API التاجر | فحص الدور | ✓ 403 |
| تاجر لا يرى مشروع تاجر آخر | `WHERE owner_id` وجلب مفرد | ✓ 404 على 3 محاور |
| لا صلاحية إدارية تلقائية | `role` = merchant في التسجيل | ✓ تجاهل `role` الواردة |
| حماية المحاولات | قفل 5 محاولات/10 دقائق للحساب + حد IP | ✓ 429 |
| طلب من أصل آخر | رفض Cross-origin | ✓ 403 |
| طلب تغيير بلا ترويسة | رفض `csrf` | ✓ 403 |
| سجل إداري | `audit_log` لكل تغيير | ✓ سطر `owner.merchant.update` |
| مصادقة مزدوجة للمالك | TOTP بـ RFC6238 بلا مكتبات | إعداد + تفعيل عبر الواجهة |
| الأسرار | على الخادم فقط | لا مفاتيح في الواجهة |

## ٥) لوحة التاجر (بدفتر V3)

`/dashboard/` بصفحات: نظرة عامة (مؤشرات حقيقية، أعلى هوامش، تحتاج مراجعة، آخر تعديلات)، المشاريع، صفحة مشروع (تصنيفات + منتجات + إضافة)، كل المنتجات، صفحة منتج (حالة محفوظة + أزرار جاهز/أرشفة/حذف)، الوصفات، الحساب.
- رحلة الإعداد: ٣ خطوات (نوع المنشأة ← الاسم ← طريقة البدء) ثم إنشاء المشروع.
- لا تكرار إعداد: المشروع والحالة يُحفظان ويُستأنفان.

## ٦) لوحة المالك (مستقلة بصريًا وأمنيًا)

`/owner-admin/` داكنة لها 11 قسمًا، **كل قسم وحدة قابلة للإضافة** (`SECTIONS` في `owner-admin/app.js` — قسم جديد = سطر واحد + دالة):
الإحصاءات · التجار (بحث/إيقاف/تنشيط) · الأنشطة والتصنيفات (إضافة/إخفاء) · اقتراحات المكونات (CRUD) · مكتبة المكونات · الذكاء الاصطناعي (نماذج/حرارة/تفعيل/سجل) · مصادر الأسعار · المحتوى والإعلانات · المظهر · سجل العمليات · الأمان والنسخ + TOTP.
